The only status legend in the tree is ASM_VALIDATION_PROGRESS.md's `untested`, `tested`, `partial`, and this slice uses those three words. They cannot say "checked against the disassembly", and they cannot split "read from the C++" from "checked against nothing": both land on `untested`, so every `untested` concept says in its body which it is. The OPEN note in SCHEMA.md stays open.

**Finding, the projection source.** Porting Status is projected from ASM_VALIDATION_PROGRESS.md rather than ASM_TO_CPP_REFERENCE.md, because the reference file has no LIB386 rows and the per-routine evidence lives in the progress doc. **Finding, relation targets.** `ports` and `verified_against` take bundle-relative paths, and an ASM routine or a test file is not a concept. This slice points `ports` at the routine's section anchor in the generated Porting Status concept, `/porting/3d.md#mulmatrixf`, and wraps the test suites as Reference concepts for `verified_against`. Rule 10 then reads as: the anchored row's status and the Quirk's `equivalence` agree.

**Finding, links and CI.** lychee refuses a root-relative link unless it is given a root directory, so `lychee.toml` sets `root_dir = "docs/knowledge"`. The consequence is that the repository's link gate does not tolerate a dangling body link inside the bundle, although rule 4 says the profile does. This slice has none. To decide: keep the gate and drop the tolerance from the schema, or exclude the bundle from lychee and let the bundle lint own body links.

**Finding, the vocabulary on new construction.** The `.rec` Format sits at `tested` on the strength of host and automation tests, which is the second evidence level, so the vocabulary holds for code with no ASM original. SOURCES code is the original C++, so for a Quirk there the top evidence level is empty by construction; ChangeCube's evidence is measurement, and the body says so.

**Finding, the schema against its own rules.** SCHEMA.md declares `type: Reference` and carries no `resource`, which its own catalogue requires, so rule 2 and rule 3 pass on it and the per-type check does not. Rule 7 as written trips on SCHEMA.md itself, which spells the double-bracket wikilink syntax out in a code span in order to forbid it; the lint has to skip code spans, or the schema. The `asm_origin` example is a line-number citation, the form AGENTS.md says rots on the next edit and nothing checks; both Quirks here write it as file and routine instead, which is greppable and is what a reader needs to land on the act. All three are for the maintainer to settle, and none is changed here.

**Finding, a Quirk needs a scope.** Reported from a concurrent recorder session. The ChangeCube quirk holds on the loose-clock `--load` path; under `--fixed-dt` the seed is 0 and deterministic, and a code comment about that configuration reads as contradicting the quirk until the two scopes are stated. This engine forks behaviour on `--load` against fresh start, pinned against host clock, and headless against windowed, so an unscoped Quirk is a wrong belief waiting for a reader to resolve the contradiction by deleting one side. Both Quirks in this slice carry a producer key `scope`; the profile should require it.

**Finding, negative space.** Same source. Three format errors in one session were each an assumption that a header field says more than it does: `engine=` is not a build identity, `mode.fixed_dt` says that the step was pinned and not when, and a torn poll stream is not detectable the way a torn chunk is. A Format that records every guarantee and none of the traps is worse than the source comments it summarises. The `.rec` Format carries a "What it does not tell you" section; the profile should make it a required body section on Format, and probably on Subsystem.

**Finding, provenance on a moving subsystem.** Same source. The recorder changed in the day this slice was written (#661 merged, two branches unpushed, a `--replay` crash being fixed), so a Subsystem or Format concept about it is current only at a commit. Both carry a producer key `as_of` naming the commit their details were read from. The profile should require it on concepts about subsystems under active change, and should say which claims in a concept are structural and which are current, since a concept that mixes them without dating is worse than grep, which at least dates itself by what is in the tree.

**Finding, one mechanism, several manifestations.** Same source. One fact (`RestoreTimer` rewinds `TimerRefHR` and not `LastTime`, so restoring one of a coupled pair is not a rewind) was rediscovered three times in one night as a proposed mechanism, a dismissed hazard and the actual blocker, by two people who had both written it down. A typed relation for "same mechanism, different manifestation" would have caught it; no instance exists in this slice, so the key is proposed here and not defined.
